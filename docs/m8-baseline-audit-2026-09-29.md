## Intended baseline and existing contract

`dml_core/scripts/production_baseline.py:20–61` implements `SQLiteBaseline`, independent of DML retrieval services. `remember(memory_id,text,vector,scope,timestamp)` commits float32 embeddings and text to SQLite with WAL and synchronous FULL. `recall(vector,scope,now,top_k=8,budget=600)` exact-filters canonical JSON scope, ranks exhaustive cosine similarity plus `0.15 / (1 + age_seconds / 3600)`, deterministically breaks ties by ID, and returns IDs/context. It clips each record to 220 characters, stops at the first candidate exceeding the `len(context)//4` budget estimator, and does not expose full record metadata or scores in results. `close()` then reopen restores committed rows.

This is append-only conventional RAG: corrections can be new timestamped records, old conflicting evidence stays available; duplicate IDs reject rather than overwrite. No mutation/supersession/delete or authority-ranking API exists. Exact scope matching isolates projects only if the caller supplies the full correct scope; there is no separate credential authorization boundary. IDs are database-global rather than scope-local. WAL is durable SQLite, not DML receipt lifecycle semantics.

`dml_core/daystrom_dml/rag_store.py::PersistentRAGStore` is a different FAISS store integrated into DML; do not substitute it for the independent baseline. `examples/bench/bench_dml_vs_rag.py` benchmarks DML retrieval modes, not this independent baseline. The old smoke runner initializes a legacy DML configuration and is not the frozen supported M7 DML candidate.

## Gaps to resolve on development cases before held-out freeze

- Keep durable storage/ranking; add separately reviewed arm orchestration with context-only and supported DML. Context-only has no hidden persistent retrieval and gets original scoped chronological inputs within the same exact model-token budget, with predeclared non-oracular compaction. Do not use the legacy two-arm retrieval smoke as M8 evidence.
- Exact model-token budgeting must replace/override the legacy approximate compaction at the wrapper boundary. Baseline cannot be restricted to 220-character snippets while DML gets more complete evidence. Common lossless source envelopes and comparable token-budget compaction must preserve source ID/time/authority/correction links visible to all arms. Reuse ranking/storage, do not create a weaker replacement.
- Let baseline issue automatic ordinary search and dependent follow-up searches with authentic results; expose baseline-neutral tool names and instructions. No DML operation IDs, receipt enums, lifecycle mutation schema or mandatory DML actions in baseline prompts. A neutral claims/citations answer contract can be shared.
- Ordinary RAG correction policy must be explicit: append corrections with timestamp and provenance, or a documented standard update/index policy selected on development data only. Leaving obsolete data without normal current-state cues would handicap it. No oracle prefiltering or truth-based removal.
- `OfflineEmbedder` is 64-dimensional SHA256 token histogram; it is a deterministic lexical smoke embedding, not semantic embedding qualification. Retrieval fairness requires exactly the same pinned embedder and chunking across RAG and DML. If retaining it, label claim narrowly; no model search is needed. The intended embedding choice must be reconciled with the supported DML candidate before execution.
- API validates stored vectors but not finite query vectors, timestamp/top_k/budget semantics, embedding identity beyond dimension, or corrupted BLOB contents. Harness should validate all inputs and pin embedding identity before development qualification; never silently repair held-out failures.
- Existing measurements include only per-query embed+retrieval wall time and hit count. No ingestion time, embedding token/work cost, update/checkpoint/WAL cost, CPU/GPU utilization, disk growth, restart latency, cache labels, actual tokenizer input/output IDs, TTFT, model/tool failures or timeouts. Add complete stage accounting, including failures and maintenance. `services/evaluation.py` already counts failed attempts and maintenance generation tokens, but lacks paired CIs, stale-answer-specific denominator and complete embedding/ingestion cost categories.
- No context-only implementation, live baseline model consumer, leakage check, development/held-out split, paired arm order, confidence intervals or M8 acceptance thresholds exist in this runner. These are open qualification gates, not reasons to replace the durable baseline.

Ledger stays M8 open: `docs/production-remaining-work-2026-09-18.md:318`; `docs/bare-metal-milestone-plan-2026-09-28.md:49` explicitly require equal resources and paired confidence intervals with predeclared quality/value/latency gates. This audit supports design review only.

## Interface and query-only comparison addendum

Exact-source blocker confirmed: `services/llama3_sft_runtime.py:36–40` requires the first system message to equal fixed DML `SYSTEM`; `llama3_sft_v3_action_input.py::source_order_request` additionally binds original DML tool schemas. Therefore the M7 consumer cannot be reused unchanged for fair context-only/RAG interfaces. A separately versioned neutral inference interface is required, preserving pinned model/adapter, tokenizer, sampling, exact IDs and budget/evidence machinery. This is interface qualification, not new training or model search. M7 source and its evidence must remain unchanged. All three arms must receive comparably qualified prompt/protocol support; forcing the old DML policy onto baselines is unacceptable.

A query-focused M8 is defensible as a memory-value comparison: authenticated non-model drivers deliver the same scoped event stream, facts, corrections and source metadata to every arm; RAG and DML expose common automatic `retrieve` semantics with genuine dependent follow-up; context-only receives the same events through bounded chronological context. DML ingestion/lifecycle and baseline standard current-view maintenance are costed. Driver decisions must depend only on explicit event fields, never the held-out answer key, and no driver may solve ambiguous source conflicts for one arm. Preserve conflicting independent sources; deterministic replacement is allowed only for explicit same-source version/correction identity. RAG retains immutable history plus a documented current view; historical-query support, if in scope, must be equally specified.

This tests whether DML's stored-state/retrieval behavior yields better cited answers under changing information and matched budgets. It does not repeat M7's model-owned mutation qualification and cannot establish autonomous memory editing, learned error recovery, or model-chosen supersession advantage. Report the exact narrower claim: externally ingested, scoped evolving-memory query workloads. Because automatic current-view normalization can eliminate DML's stale-data advantage, do not weaken the baseline if no meaningful advantage remains; keep M8 open when predeclared thresholds fail.

Additional fairness conditions: all event ingestion/maintenance costs belong to the receiving arm, and context processing/compaction is charged to context-only; no external lookup for that arm. Zero-shot query-only prompts should not tell context-only to retrieve or mention unavailable lifecycle actions. DML adapter remains enabled. A common adapter setting across all three primary arms controls model identity but can still confer DML-trained-interface familiarity; if baseline base-only sensitivity arms are used, predeclare their role and never choose the better held-out result after seeing it. Pilot neutral automatic retrieval and valid cited finals for all arms on development data before freezing; inability to support a baseline fairly is a harness qualification failure, not a baseline outcome.
