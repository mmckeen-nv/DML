# M8 development foundation — September 29, 2026

The [reviewed fairness proposal](m8-fairness-manifest-2026-09-29.md) now has separately versioned development components for context-only, independent persistent RAG and genuine DML memory. **M8 remains open. This is neither a live model qualification nor an execution freeze.** The [compact evidence record](artifacts/m8-development-foundation-2026-09-29.json) binds the reviewed source and local tests. Historical M7 profiles, source files, acceptance gates and campaigns are unchanged.

## Implemented and checked

- `m8_memory_baseline.py` reuses the existing SQLite baseline's WAL/FULL storage and exact cosine/recency ranking formula. A transactional provenance table applies explicit same-source correction eligibility before top-k; immutable history and independent-source conflicts remain. Shared scope/int64/time/vector validation and whole-record presentation replace neither the old baseline nor its historical smoke behavior. A bounded chronological context buffer performs no retrieval.
- `m8_protocol.py` defines a neutral policy and automatic retrieval-only interface for persistent arms. Context-only receives inline source envelopes. It reuses the original strict action/final parser, rejects unadvertised tools and repaired prose, requires visible supporting citations, escapes transport controls, and binds exact rendered input IDs plus output reserve. A separate domain verifier must establish factual support; citation visibility alone is insufficient. Policy/schema identities are new and do not impersonate the M7 runtime.
- `m8_dml_memory.py` invokes actual supported-profile receipted ingestion, supersession and retrieval. It maps authentic selected records to common source IDs, retains raw receipts in a hash-chained JSONL file, and verifies the complete owned-scope authority before operations and after retrieval. A partial append/supersede, unknown state, extra row, retirement or external alteration blocks continuation rather than triggering mutation retries. The chain still needs an external freeze hash; it is not protection against an adversary rewriting the complete file.
- `m8_accounting.py` records every admitted input/step and returned output, preserving failures, unknown usage, late completions and overrun tokens. The original six-call, token and wall ceilings apply. Embedding units remain separate; failure-inclusive token cost uses correct successes as its denominator. This in-process ledger is not yet durable execution supervision or complete compute-cost instrumentation.

The focused suite passed **128 tests, zero failures/errors/skips**: 90 new M8 controls and 38 existing outcome, episode-tool and Llama runtime controls. The three-arm integration uses real stores and DML receipts but **scripted actions and an explicit byte-tokenizer double**. It verifies plumbing, not model choice, semantic embedding quality or real tokenizer parity. Existing fixture embeddings are used only in these unit controls. Ruff passes on all nine new code/test files.

Independent review required complete owned-state drift checks and aligned admission rules; both are implemented with regressions. It also identified the following unresolved evaluation prerequisites. No new training, model search, model loading, learned-embedding inference or held-out workload execution occurred. Station services were not changed.

## Concrete execution blockers

1. **Historical event-clock parity.** The supported DML append API records `time.time()` as the authority timestamp; ranking and recent fallback use that value. A source timestamp in metadata and `as_of` on retrieval do not fix the mismatch with RAG's explicit event time. The bridge exposes `event_clock_qualified=False` and never patches the clock or rewrites committed state. Proposed next design: a separately versioned authenticated ingestion API/profile binding finite event time into the canonical request, receipt and idempotency digest while retaining commit time separately. It needs independent API review and boundary/restart/replay tests; the old API must retain its behavior.
2. **Common correction authority.** DML legitimately rejects an untrusted replacement for supersession, whereas the independent RAG current view can accept that source correction. Tests retain the real DML rejection and partial-ingestion evidence. Trusted-source controls do not establish general parity. Define and review identical externally authenticated event/source authority and conflict-disposition rules before evaluation; do not silently label all source content trusted or weaken RAG to obtain a win. Source text remains untrusted as instructions in every arm.
3. **Live neutral runtime qualification.** The new protocol has no admitted GPU generation consumer yet. Bind actual vendor tokenizer/template, model/adapter/grammar/sampler, exact token evidence and all-arm protocol competence. Do not relabel the old DML-only renderer.
4. **Execution, embedding and cost qualification.** Admit the pinned semantic embedding runtime, implement durable dispatch/timeouts and full ingestion/retrieval/maintenance/CPU/GPU/cache metering, and qualify cache ownership and complete source attestation. Local unit-test timing is not a performance claim.
5. **Workloads and inference.** An independent non-training-author must audit and seal fresh held-out data before model pilot. Generator/order/truth hashes, prospective confidence-interval boundary coverage and full-conjunction power calibration, development-only pilot and resource forecast remain pending. No held-out cases were generated or inspected in this tranche.

Complete these prerequisites, obtain exact-source CI and independent execution approval, then freeze a complete campaign. No evaluation command or shortcut is added here. Benchmark completion alone cannot close M8; the original reviewed value and safety gates still govern promotion.
