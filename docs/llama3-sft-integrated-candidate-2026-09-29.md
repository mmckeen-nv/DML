# Registered Llama 3 SFT candidate

Profile: `llama3-8b-instruct-sft-v2-bf16-action-json-v1`. This separately versioned,
enabled-only consumer integrates the [qualified synthetic checkpoint](llama3-8b-sft-v2-2026-09-29.md)
with DML's standard V2 episode contracts, selected-profile tool gateway, durable
supervisor and campaign evidence checker. Integration does not itself qualify
this producer or close M7. Earlier profiles and retained campaigns stay separate.

The snapshot manifest binds the original Llama 3 revision and complete official
file inventory, final scheduled SFT v2 adapter, tokenizer/template, container
image and runtime dependencies. The consumer preserves source dictionary order
inside the trained logical-message transport, exact input/output token IDs,
authenticated single-use compiled inputs, the 8,192-token request window, original
sampling and constrained action grammar. It cannot fall back to CPU inference,
a different checkpoint, a disabled adapter or another model revision.

Normal outputs go through the existing action parser, authorization boundary and
claims/citations verifier. Failed executions retain their outer exception and
available raw runtime response, including partial token IDs and decode failures.
Interrupted workers retain the acknowledged dispatch and explicitly unavailable
response. Unknown consumption remains unknown; no failure becomes a successful
action or final. These evidence fields are exclusive to the new profile.

`llama3_sft_synthetic` predeclares fresh cases through the existing planning and
readiness fixture constructors and scorers. Planning must pass 2/2 before any of
the four readiness cases starts. Neither stage permits retries, forced actions,
output repair or model changes. Both suites are frozen before generation.

The campaign freezer requires clean exact-source CI, runtime admission, durable
execution qualification, reviewed deployment configuration and both evidence
replays for each qualification stage. It preserves the original nine tasks,
budgets, corpus and M7 gates, including both named-task requirements. The new
CPU CI lane verifies source and offline controls only; GPU admission remains a
separate required gate on the station.

Raw manifests, weights, datasets, prompts, model responses and authority journals
remain on the station. Publish only compact outcomes and hashes. Nothing is
merged, and no nine-task campaign is authorized by this document alone.
